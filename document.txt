## 3. Dataset Details

Humne Adult Census Income dataset use kiya.

**Dataset path:** `data/adult.csv`

Dataset ke results:

* Total rows: 32,561
* Total columns: 15
* Target column: `income`
* Features: 14
* Target classes: `<=50K` and `>50K`

Dataset mein age, education, occupation, work hours, capital gain, marital status aur doosri demographic information shamil hain.

### Data preprocessing

Training script mein:

* Target column identify kiya jata hai.
* Features aur target ko separate kiya jata hai.
* Invalid target rows remove ki jati hain.
* Categorical columns ko `pd.get_dummies()` se encode kiya jata hai.
* Missing feature values ko zero se fill kiya jata hai.
* Dataset ko training aur testing subsets mein divide kiya jata hai.
* `stratify=y` se class proportions preserve ki jati hain.

Train-test split:

* Training data: 80%
* Testing data: 20%
* Random state: 42

## 4. Model Training

**File:** `train.py`

Humne Scikit-learn ka Random Forest classifier use kiya.

Model configuration:

```python

    n_estimators=100,
    random_state=42,
    n_jobs=-1

### Training command

```

### Is command se kya hota hai?

2. Features preprocess hote hain.
3. Training aur testing data banta hai.
4. Random Forest model train hota hai.
5. Predictions generate hoti hain.
6. Accuracy, precision, recall aur F1-score calculate hote hain.
7. Classification report aur confusion matrix print hoti hain.
8. Parameters aur metrics MLflow mein log hote hain.
9. Model `model.joblib` mein save hota hai.
10. Model MLflow ke through log aur register hota hai.

| Accuracy           | 85.06% |
| Weighted Precision | 84.49% |
| Weighted Recall    | 85.06% |
| Weighted F1-score  | 84.64% |

| Income class | Precision | Recall | F1-score |

Model overall achha perform kar raha hai, lekin `>50K` class ka recall 0.62 hai. Iska matlab higher-income class ke kuch actual examples model miss kar raha hai. Future improvement mein class imbalance, threshold tuning aur alternative models evaluate kiye ja sakte hain.

## 13. GitHub Actions CI/CD Pipeline

**Workflow file:** `.github/workflows/ml-pipeline.yml`

GitHub Actions pipeline ko push, pull request aur manual workflow dispatch par trigger karne ke liye configure kiya.

### Pipeline flow

```text
Code Push / Pull Request
          |
          v
   Checkout Repository
          |
          v
      Setup Python
          |
          v
   Install Dependencies
          |
          v
    Validate Dataset
          |
          v
      Train Model
          |
          v
     Run Pytest Tests
          |
          v
   Monitor Data Drift
          |
          v
Monitor Model Performance
          |
          v
 Enforce Performance Limits
          |
          v
  Upload Monitoring Reports
```

### Workflow configuration

```yaml
name: MLOps CI Pipeline

on:
  push:
    branches:
      - main
      - feature/advanced-mlops
  pull_request:
    branches:
      - main
  workflow_dispatch:

jobs:
  train-test-monitor:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Setup Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt

      - name: Validate dataset
        run: python validate_data.py

      - name: Train model and log MLflow metrics
        run: python train.py

      - name: Run automated tests
        run: python -m pytest tests/ -v

      - name: Monitor data drift
        run: python monitor_drift.py

      - name: Monitor model performance
        run: python monitor_performance.py

      - name: Enforce performance thresholds
        run: |
          python -c "import json,sys; p=json.load(open('monitoring/performance_report.json')); print('Accuracy:', p['accuracy']); print('Weighted F1:', p['weighted_f1']); print('Status:', p['status']); sys.exit(0 if p['status'] == 'PASS' else 1)"

      - name: Upload monitoring reports
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: monitoring-reports
          path: monitoring/
          if-no-files-found: warn
          retention-days: 7
```

### Pipeline ka purpose

* Code push hone par automated checks chalana.
* Dataset validate karna.
* Model train karna.
* Tests run karna.
* Drift aur performance reports generate karna.
* Performance threshold fail hone par job fail karna.
* Monitoring reports ko artifact ke roop mein upload karne ki koshish karna.

### Important workflow status

Pehle ek workflow run successfully complete hua tha aur teen tests pass hue the. Advanced monitoring changes add karne ke baad ek run `validate_data.py` missing hone ki wajah se fail hua. Baad ke run mein YAML syntax error report hua.

Isliye final documentation mein CI/CD setup ko implemented, lekin **latest workflow ko green status ke saath re-verify karna baaki** maana jayega. Updated YAML save aur push karne ke baad latest run verify karna zaroori hai.

## 18. Remaining Advanced MLOps Improvements

### A. Automated model promotion

Training ke baad model ko automatically promote karne se pehle evaluation thresholds aur model quality checks enforce karne chahiye.

### B. Production data drift

Production se aane wale naye inputs ko reference data se compare karna chahiye. Sirf original dataset ko dobara evaluate karna production drift monitoring ke liye sufficient nahi hai.

### C. Data validation improvements

Question-mark values, missing values, data types, valid ranges aur target classes ko explicitly validate karna chahiye.

### D. Automated deployment

Approved model version ko deployment environment mein publish karne ka process configure karna hoga. GitHub Actions ka successful hona akela model deployment complete hone ka proof nahi hai.

### E. Rollback

Agar deployed model ka performance threshold fail ho, to previous verified model version par wapas switch karne ki tested strategy implement karni hogi.

### F. Monitoring alerts

Performance ya drift thresholds fail hone par logs ke saath notification mechanism configure kiya ja sakta hai.

### G. Reproducibility and security

* Dependencies ko version-pin karna.
* Dataset versions track karna.
* Model artifacts aur MLflow tracking data ka backup rakhna.
* Git mein virtual environment aur unnecessary generated files commit na karna.
* Sensitive credentials ko GitHub Secrets mein rakhna.
